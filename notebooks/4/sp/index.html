Problem Formulation In Words¶

Minimize total cost, subject to the following constraints:

  • Plant up to 500 acres.

  • Need at least 200 tons of wheat (for animals).

  • Need at least 240 tons of corn (for animals).

  • Sugar beet sales must be less than or equal to the yield from the farm.

  • All variables are nonnegative.

  • Up to 6000 tons of sugar beets can be sold at a favorable price.

Create a function to build a pyomo model for the farmer’s problem with crop yields as an input

Units. Land is in acres, crops in metric tons, money in dollars, and yields in tons per acre. The literal coefficients carry their units inline --- 150 * USD_PER_ACRE rather than a bare 150 --- and each builder ends with assert_units_consistent, which raises if any of the constraints or the objective does not balance. A units declaration nobody checks only looks verified. The deterministic model has 9 variables and 4 explicit inequalities, plus bounds; its premium sales cap is a variable bound. The three-scenario extensive form has 21 variables and 10 explicit inequalities plus bounds. None is an equality, so subtracting these inequalities would not be a degrees-of-freedom calculation.

# Deterministic LP: acres chosen for a specified yield, costs in dollars.
import pyomo.environ as pyo
from pyomo.environ import units as u
from pyomo.util.check_units import assert_units_consistent

# Pyomo's unit library has acres and metric tons but no money, so declare one.
u.load_definitions_from_strings(["USD = [currency]"])

# Shorthands for the three compound units this problem uses
USD_PER_ACRE = u.USD / u.acre
USD_PER_TON = u.USD / u.metric_ton
TON_PER_ACRE = u.metric_ton / u.acre

### Create a function to build a pyomo model for the farmer's problem with crop yields as an input


def build_model(yields):
    """
    Code adapted from https://mpi-sppy.readthedocs.io/en/latest/examples.html#examples

    Arguments:
        yields: Yield information as a list, following the rank [wheat, corn, beets]

    Return:
        model: farmer problem model
    """
    model = pyo.ConcreteModel()

    # Define sets
    all_crops = ["WHEAT", "CORN", "BEETS"]
    purchase_crops = ["WHEAT", "CORN"]
    sell_crops = ["WHEAT", "CORN", "BEETS_FAVORABLE", "BEETS_UNFAVORABLE"]

    model.CROPS = pyo.Set(initialize=all_crops)
    model.FEED_CROPS = pyo.Set(initialize=purchase_crops)
    model.SALE_TYPES = pyo.Set(initialize=sell_crops)

    # Crops field allocation [acre]
    model.acreage = pyo.Var(model.CROPS, domain=pyo.NonNegativeReals, units=u.acre)
    # How many tons of crops to purchase [t]
    model.purchases = pyo.Var(
        model.FEED_CROPS, domain=pyo.NonNegativeReals, units=u.metric_ton
    )
    # How many tons of crops to sell [t]
    model.sales = pyo.Var(
        model.SALE_TYPES, domain=pyo.NonNegativeReals, units=u.metric_ton
    )

    # pyo.Objective function [USD]
    model.planting_cost = (
        150 * USD_PER_ACRE * model.acreage["WHEAT"]
        + 230 * USD_PER_ACRE * model.acreage["CORN"]
        + 260 * USD_PER_ACRE * model.acreage["BEETS"]
    )
    model.purchase_cost = (
        238 * USD_PER_TON * model.purchases["WHEAT"]
        + 210 * USD_PER_TON * model.purchases["CORN"]
    )
    model.sales_revenue = (
        170 * USD_PER_TON * model.sales["WHEAT"]
        + 150 * USD_PER_TON * model.sales["CORN"]
        + 36 * USD_PER_TON * model.sales["BEETS_FAVORABLE"]
        + 10 * USD_PER_TON * model.sales["BEETS_UNFAVORABLE"]
    )
    # Maximize the Obj is to pyo.minimize the negative of the Obj
    model.objective = pyo.Objective(
        expr=model.planting_cost + model.purchase_cost - model.sales_revenue,
        sense=pyo.minimize,
    )

    # Constraints

    # Plant at most 500 acres [acre]
    model.land_limit = pyo.Constraint(expr=pyo.summation(model.acreage) <= 500 * u.acre)
    # Animal feed requirements and beet sales limits [t]
    model.wheat_feed = pyo.Constraint(
        expr=yields[0] * TON_PER_ACRE * model.acreage["WHEAT"]
        + model.purchases["WHEAT"]
        - model.sales["WHEAT"]
        >= 200 * u.metric_ton
    )
    model.corn_feed = pyo.Constraint(
        expr=yields[1] * TON_PER_ACRE * model.acreage["CORN"]
        + model.purchases["CORN"]
        - model.sales["CORN"]
        >= 240 * u.metric_ton
    )
    model.beet_balance = pyo.Constraint(
        expr=yields[2] * TON_PER_ACRE * model.acreage["BEETS"]
        - model.sales["BEETS_FAVORABLE"]
        - model.sales["BEETS_UNFAVORABLE"]
        >= 0 * u.metric_ton
    )
    model.sales["BEETS_FAVORABLE"].setub(6000)

    # Raises UnitsError if any constraint or the objective is inconsistent
    assert_units_consistent(model)

    return model
# Solve the Optimization Problem with Perfect yields
yields_perfect = [2.5, 3, 20]
model = build_model(yields_perfect)
solver = pyo.SolverFactory("appsi_highs")
results = solver.solve(model)
assert pyo.check_optimal_termination(results), (
    f"Solve failed: status={results.solver.status}, "
    f"termination={results.solver.termination_condition}"
)

# Define a function for printing the optimal solution


def print_opt_sol(model, yields):
    """
    Arguments:
        model: solved farmer problem model
        yields: the yields [wheat, corn, beets] this model was built with, in
            T/acre. These are needed to report the production, and they differ
            from scenario to scenario.

    Return:
        Prints the optimal solution
    """
    print("===Optimal solution for specified yields===")

    print("Culture.         | ", "Wheat |", "Corn  |", "Sugar Beets |")
    print(
        "Surface (acres)  | ",
        f'{pyo.value(model.acreage["WHEAT"]):.1f}',
        "|",
        f'{pyo.value(model.acreage["CORN"]):.1f}',
        " |",
        f'{pyo.value(model.acreage["BEETS"]):.1f}',
        " |",
    )
    print(
        "Yield (T)        | ",
        f'{pyo.value(model.acreage["WHEAT"])*yields[0]:.1f}',
        "|",
        f'{pyo.value(model.acreage["CORN"])*yields[1]:.1f}',
        "|",
        f'{pyo.value(model.acreage["BEETS"])*yields[2]:.1f}',
        "|",
    )
    print(
        "Sales (T)        | ",
        f'{pyo.value(model.sales["WHEAT"]):.1f}',
        "|",
        f'{pyo.value(model.sales["CORN"]):.1f}',
        "  |",
        f'{pyo.value(model.sales["BEETS_FAVORABLE"]) + pyo.value(model.sales["BEETS_UNFAVORABLE"]):.1f}',
        "|",
    )
    print(
        "Purchases (T)    | ",
        f'{pyo.value(model.purchases["WHEAT"]):.1f}',
        "  |",
        f'{pyo.value(model.purchases["CORN"]):.1f}',
        "  |",
        "-",
        "     |",
    )

    profit = -pyo.value(model.objective)
    print("Overall profit: $", f"{profit:.1f}")

    return profit


profit_perfect = print_opt_sol(model, yields_perfect)

This solution is easy to understand:

  • Devote enough land to wheat and corn production to meet the feeding requirement

  • Plant wheat in the rest of the land

Changes that can invalidate this data-specific heuristic include new constraints or different objective coefficients:

  • Market prices change

  • Yield is uncertain

  • Planting cost materials, water, labor...

  • Crop rotation

A representation of the uncertainty would be to assume that years are good, fair, or bad for all crops, resulting in above average, average, or below average yields for all crops. Three scenarios are defined as:

  • Above average yield (+20%)

  • Average yield (base case)

  • Below average yield (-20%)

Stochastic Programming¶

Stochastic programming assigns a probability model to uncertain inputs. A deterministic model treats its input parameters as fixed, which can be a modeling approximation.

Vectors are bold; scalar components are plain. Let x\mathbf{x}x be the first-stage decision and y(Ξ)\mathbf{y}(\boldsymbol\Xi)y(Ξ) the recourse selected after observing uncertainty:

min⁡x,y(⋅)E[f(x,y(Ξ),Ξ)]\min_{\mathbf x,\mathbf y(\cdot)}\mathbb E[f(\mathbf x,\mathbf y(\boldsymbol\Xi),\boldsymbol\Xi)]x,y(⋅)min​E[f(x,y(Ξ),Ξ)]
(2)

subject to g(x,y(Ξ),Ξ)≤0\mathbf g(\mathbf x,\mathbf y(\boldsymbol\Xi),\boldsymbol\Xi)\le\mathbf0g(x,y(Ξ),Ξ)≤0 and h(x,y(Ξ),Ξ)=0\mathbf h(\mathbf x,\mathbf y(\boldsymbol\Xi),\boldsymbol\Xi)=\mathbf0h(x,y(Ξ),Ξ)=0 almost surely. The fixed first-stage vector cannot depend on the unobserved realization.

Birge and Louveaux (2011), 2nd ed., §1.1c, pp. 10–11; §2.4, pp. 59–60.

Key Concepts¶

Probability review¶

For a fair six-sided die, each realization ξ∈{1,…,6}\xi\in\{1,\ldots,6\}ξ∈{1,…,6} has probability mass p(ξ)=1/6p(\xi)=1/6p(ξ)=1/6.

  • Discrete masses satisfy 0≤p(ξ)≤10\le p(\xi)\le10≤p(ξ)≤1 and sum to one.

  • A continuous density is nonnegative and integrates to one; its height can exceed one.

  • For example, a uniform variable on (0,1/2)(0,1/2)(0,1/2) has density 2 on its support.

Birge and Louveaux (2011), 2nd ed., §2.1, pp. 55–57.

Continuous-distribution expectation¶

For an integrable function and a distribution with density,

E[f(Ξ)]=∫Θf(ξ)p(ξ) dξ.\mathbb E[f(\boldsymbol\Xi)]=\int_\Theta f(\boldsymbol\xi)p(\boldsymbol\xi)\,d\boldsymbol\xi.E[f(Ξ)]=∫Θ​f(ξ)p(ξ)dξ.
(3)

A continuous support can have infinitely many points in a finite-dimensional space. An unrestricted recourse policy is a function; the number of outcomes is not the dimension of the random vector.

Birge and Louveaux (2011), 2nd ed., §1.1d, pp. 11–14; §2.4, pp. 59–60.

Use scenarios ξs\boldsymbol\xi_sξs​ with nonnegative weights psp_sps​ summing to one:

(4)

For an exactly finite distribution the sum is exact. A scenario approximation to a continuous distribution introduces approximation error.

Include uncertainty in the Farmer’s Problem (two-stage stochastic program)¶

Now the farmer wants to assess the benefits and losses of each decision in each situation.

Decisions on land assignment (x1x_1x1​, x2x_2x2​, x3x_3x3​) have to be taken now, but sales and purchases (wi,i=1,...,4w_i, i=1,...,4wi​,i=1,...,4, yj,j=1,2y_j, j=1,2yj​,j=1,2) depend on the yields. This forms the two-stage stochastic program:

  1. Stage 1 decisions: land assignments (x1x_1x1​, x2x_2x2​, x3x_3x3​)

  2. Uncertainty is realized

  3. Stage 2 decisions: wait-and-see (sales and purchases)

It is useful to index those decisions by a scenario index s=1,2,3s=1,2,3s=1,2,3 according to above average, average or below average yields, respectively. This creates a new set of variables wi,s,i=1,2,3,4,s=1,2,3w_{i,s}, i=1,2,3,4, s=1,2,3wi,s​,i=1,2,3,4,s=1,2,3 and yj,s,j=1,2,s=1,2,3.y_{j,s}, j=1,2, s=1,2,3.yj,s​,j=1,2,s=1,2,3. For e.g., w3,2w_{3,2}w3,2​ represents the amount of sugar beets sold at the favorable price if yields are average.

Blocks make the two-stage structure explicit. In the code below, the stage 1 decision acreage sits on the model itself, and each scenario gets its own Block holding that scenario’s stage 2 decisions purchases and sales together with the three constraints they appear in. This is the indexed-Block pattern from Chapter 8 of Pyomo -- Optimization Modeling in Python: one rule describes a single scenario, and Pyomo builds one copy of it per scenario.

The alternative is to hang a scenario index off every stage 2 variable --- model.sales[crop, scenario] --- which gives the same optimization problem, but nothing in the code then says which variables are decided now and which wait for the yield to be realized.

# Extensive form: one shared acreage vector, separate purchases/sales per scenario.
# Nonanticipativity comes from sharing the first-stage variables.
def build_sp_model(yields):
    """
    Code adapted from https://mpi-sppy.readthedocs.io/en/latest/examples.html#examples
    It specifies the extensive form of the two-stage stochastic programming

    Arguments:
        yields: Yield information as a list, following the rank [wheat, corn, beets]

    Return:
        model: farmer problem model
    """
    model = pyo.ConcreteModel()

    all_crops = ["WHEAT", "CORN", "BEETS"]
    purchase_crops = ["WHEAT", "CORN"]
    sell_crops = ["WHEAT", "CORN", "BEETS_FAVORABLE", "BEETS_UNFAVORABLE"]
    scenarios = ["ABOVE", "AVERAGE", "BELOW"]

    model.CROPS = pyo.Set(initialize=all_crops)
    model.FEED_CROPS = pyo.Set(initialize=purchase_crops)
    model.SALE_TYPES = pyo.Set(initialize=sell_crops)
    model.SCENARIOS = pyo.Set(initialize=scenarios)

    # Yield multiplier for each scenario, +/- 20% around the mean [dimensionless]
    yield_factor = {"ABOVE": 1.2, "AVERAGE": 1.0, "BELOW": 0.8}

    # Stage 1: fields allocation, chosen before the yields are known [acre]
    model.acreage = pyo.Var(model.CROPS, domain=pyo.NonNegativeReals, units=u.acre)

    # Stage 1 cost [USD]
    model.planting_cost = (
        150 * USD_PER_ACRE * model.acreage["WHEAT"]
        + 230 * USD_PER_ACRE * model.acreage["CORN"]
        + 260 * USD_PER_ACRE * model.acreage["BEETS"]
    )

    # Stage 1 constraint: plant at most 500 acres [acre]
    model.total_land_constraint = pyo.Constraint(
        expr=pyo.summation(model.acreage) <= 500 * u.acre
    )

    def scenario_block_rule(b, scenario):
        """Populate the block for one scenario.

        The first argument of a block rule is the block being built, not the
        model, so the stage 1 variable is reached through `model` from the
        enclosing scope.
        """
        # Stage 2: how many tons of crops to purchase in this scenario [t]
        b.purchases = pyo.Var(
            model.FEED_CROPS, domain=pyo.NonNegativeReals, units=u.metric_ton
        )
        # Stage 2: how many tons of crops to sell in this scenario [t]
        b.sales = pyo.Var(
            model.SALE_TYPES, domain=pyo.NonNegativeReals, units=u.metric_ton
        )

        # Purchase cost in this scenario [USD]
        b.purchase_cost = (
            238 * USD_PER_TON * b.purchases["WHEAT"]
            + 210 * USD_PER_TON * b.purchases["CORN"]
        )
        # Sales revenue in this scenario [USD]
        b.sales_revenue = (
            170 * USD_PER_TON * b.sales["WHEAT"]
            + 150 * USD_PER_TON * b.sales["CORN"]
            + 36 * USD_PER_TON * b.sales["BEETS_FAVORABLE"]
            + 10 * USD_PER_TON * b.sales["BEETS_UNFAVORABLE"]
        )

        # Yields realized in this scenario [t/acre]
        crop_yield = [y * yield_factor[scenario] for y in yields]

        # Satisfy the wheat feed requirement [t]
        b.wheat_constraint = pyo.Constraint(
            expr=crop_yield[0] * TON_PER_ACRE * model.acreage["WHEAT"]
            + b.purchases["WHEAT"]
            - b.sales["WHEAT"]
            >= 200 * u.metric_ton
        )
        # Satisfy the corn feed requirement [t]
        b.corn_constraint = pyo.Constraint(
            expr=crop_yield[1] * TON_PER_ACRE * model.acreage["CORN"]
            + b.purchases["CORN"]
            - b.sales["CORN"]
            >= 240 * u.metric_ton
        )
        # Beet sales cannot exceed beet production [t]
        b.beets_constraint = pyo.Constraint(
            expr=crop_yield[2] * TON_PER_ACRE * model.acreage["BEETS"]
            - b.sales["BEETS_FAVORABLE"]
            - b.sales["BEETS_UNFAVORABLE"]
            >= 0 * u.metric_ton
        )

        # Cap sales at the favorable price [t]
        b.sales["BEETS_FAVORABLE"].setub(6000)

    # One block per scenario: identical structure, different yield data
    model.scenarios = pyo.Block(model.SCENARIOS, rule=scenario_block_rule)

    # pyo.Objective function [USD]
    model.objective = pyo.Objective(
        expr=model.planting_cost
        + 1 / 3 * sum(model.scenarios[s].purchase_cost for s in scenarios)
        - 1 / 3 * sum(model.scenarios[s].sales_revenue for s in scenarios),
        sense=pyo.minimize,
    )

    # Raises UnitsError if any constraint or the objective is inconsistent
    assert_units_consistent(model)

    return model
### calculate two-stage stochastic problem

Expected value of perfect information¶

For profit maximization, EVPI=WS−RP≈$7,015.56EVPI=WS-RP\approx\$7,015.56EVPI=WS−RP≈$7,015.56. It is the model’s increase in optimal expected profit if yields are known before planting. It bounds a risk-neutral decision maker’s willingness to pay for perfect yield information within this model, not the price of an arbitrary forecast. See Birge and Louveaux, §4.1, pp. 163–164.

Modeling qualifications¶

  • A continuous random vector has uncountably many outcomes but can have finite dimension. A probability density can exceed one; its integral is one.

  • These historical farmer data are Birge and Louveaux (2011), 2nd ed., §1.1a–c, pp. 4–11. They are not current crop prices or policy.

  • The acreage heuristic applies to this data set. Higher purchase prices alone do not imply that buying feed is always suboptimal; the low-yield optimum buys corn.

  • Information values use §§4.1–4.3, pp. 163–166. Stage decisions are distinguished by information timing, not expense or irreversibility.
