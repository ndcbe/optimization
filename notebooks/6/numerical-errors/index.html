Numerical Errors: Roundoff, Cancellation, and Conditioning

Main idea: Computers store real numbers approximately. This page computes the examples behind the Floating point, forward error, backward error and Condition number sections of the Linear Algebra Review lecture, so that you can see the results. For the derivations, see Watkins (2002), Chapter 2, and Higham (2002), Chapters 1 and 2.

1. Machine epsilon and unit roundoff¶

Storing a real number xxx in the floating-point range rounds it: fl(x)=x(1+δ)\mathrm{fl}(x) = x(1+\delta)fl(x)=x(1+δ) with ∣δ∣≤u|\delta| \le u∣δ∣≤u.

  • eps =2−52≈2.2×10−16= 2^{-52} \approx 2.2 \times 10^{-16}=2−52≈2.2×10−16 is the spacing between 1 and the next number a computer can store.

  • Rounding goes to the nearest stored number, so each stored number is off by a relative error of at most half the spacing: the unit roundoff u=2−53≈1.1×10−16u = 2^{-53} \approx 1.1 \times 10^{-16}u=2−53≈1.1×10−16.

eps = np.finfo(float).eps
u = eps / 2
print(f"eps = {eps:.3e} = 2^-52: {eps == 2.0**-52}")
print(f"np.spacing(1.0) = {np.spacing(1.0):.3e}")
print(f"u   = {u:.3e} = 2^-53: {u == 2.0**-53}")

Adding eps to 1 gives the next stored number. Adding uuu is a tie halfway between two stored numbers, and the round-to-even rule returns 1.

2. Cancellation¶

Subtracting two nearly equal numbers cancels the digits they share. Consider (1−cos⁡x)/x2(1-\cos x)/x^2(1−cosx)/x2, whose true value tends to 1/21/21/2 as x→0x \to 0x→0. The identity 1−cos⁡x=2sin⁡2(x/2)1-\cos x = 2\sin^2(x/2)1−cosx=2sin2(x/2) gives the same function without a subtraction.

print(f"{'x':>8}  {'(1-cos x)/x^2':>16}  {'2 sin^2(x/2)/x^2':>18}")
for k in range(1, 9):

    naive = (1 - np.cos(x)) / x**2
    stable = 2 * np.sin(x / 2)**2 / x**2

3. The quadratic formula¶

For x2+108x+1=0x^2 + 10^8 x + 1 = 0x2+108x+1=0 the small root is close to -10-8. The usual formula subtracts two nearly equal numbers, because b2−4ac≈b\sqrt{b^2 - 4ac} \approx bb2−4ac​≈b. Multiplying numerator and denominator by the conjugate gives an equivalent formula that only adds two positive numbers:

x=−b+b2−4ac2a=−2cb+b2−4ac.x = \frac{-b + \sqrt{b^2-4ac}}{2a} = \frac{-2c}{b + \sqrt{b^2-4ac}} .x=2a−b+b2−4ac​​=b+b2−4ac​−2c​.
(1)

The problem is well conditioned; only the formula is unstable. We use 50-digit decimal arithmetic to get a reference value.

a, b, c = 1.0, 1e8, 1.0
disc = np.sqrt(b**2 - 4*a*c)
x_formula = (-b + disc) / (2*a)
x_conj    = -2*c / (b + disc)

getcontext().prec = 50
A, B, C = Decimal(1), Decimal(10)**8, Decimal(1)
x_ref = float((-2*C) / (B + (B**2 - 4*A*C).sqrt()))

print(f"{'method':<22}{'small root':>22}{'relative error':>18}")
for name, val in [("quadratic formula", x_formula), ("conjugate rewrite", x_conj)]:
    print(f"{name:<22}{val:22.15e}{abs(val - x_ref)/abs(x_ref):18.2e}")
print(f"{'reference (50 digits)':<22}{x_ref:22.15e}")

4. Forward error, backward error, and K(A)K(\mathbf{A})K(A)¶

For Ax=b\mathbf{Ax} = \mathbf{b}Ax=b and a computed solution x^\hat{\mathbf{x}}x^, with all norms the 2-norm:

  • Forward error: ∥x^−x∥/∥x∥\|\hat{\mathbf{x}} - \mathbf{x}\| / \|\mathbf{x}\|∥x^−x∥/∥x∥. How wrong is the answer?

  • Backward error: the smallest ∥ΔA∥/∥A∥\|\Delta\mathbf{A}\|/\|\mathbf{A}\|∥ΔA∥/∥A∥ such that (A+ΔA)x^=b(\mathbf{A}+\Delta\mathbf{A})\hat{\mathbf{x}} = \mathbf{b}(A+ΔA)x^=b. What problem did we actually solve? It is computable: with the residual r^=b−Ax^\hat{\mathbf{r}} = \mathbf{b} - \mathbf{A}\hat{\mathbf{x}}r^=b−Ax^,

backward error=∥r^∥∥A∥ ∥x^∥(Higham, Theorem 7.1, with E=A, f=0).\text{backward error} = \frac{\|\hat{\mathbf{r}}\|}{\|\mathbf{A}\|\,\|\hat{\mathbf{x}}\|} \qquad \text{(Higham, Theorem 7.1, with } \mathbf{E} = \mathbf{A},\ \mathbf{f} = \mathbf{0}).backward error=∥A∥∥x^∥∥r^∥​(Higham, Theorem 7.1, with E=A, f=0).
(2)

The rule of thumb is: forward error ≲K(A)×\lesssim K(\mathbf{A}) \times≲K(A)× backward error, and about log⁡10K(A)\log_{10} K(\mathbf{A})log10​K(A) of the roughly 16 digits are lost.

The Hilbert matrix {A}ij=1/(i+j−1)\{\mathbf{A}\}_{ij} = 1/(i+j-1){A}ij​=1/(i+j−1) is a classic ill-conditioned example. We choose x=1\mathbf{x} = \mathbf{1}x=1 and set b=Ax\mathbf{b} = \mathbf{Ax}b=Ax, so b\mathbf{b}b is itself rounded.

rows = []
for n in range(2, 13):
    A = linalg.hilbert(n)
    x = np.ones(n)
    b = A @ x
    xhat = linalg.solve(A, b)
    r = b - A @ xhat
    fwd = np.linalg.norm(xhat - x) / np.linalg.norm(x)
    bwd = np.linalg.norm(r) / (np.linalg.norm(A, 2) * np.linalg.norm(xhat))
    K = np.linalg.cond(A)
    rows.append((n, K, bwd, fwd, K * bwd))

print(f"{'n':>3} {'K(A)':>10} {'backward':>10} {'forward':>10} {'K*backward':>11} {'digits lost':>12} {'digits correct':>15}")

Read the table from left to right:

  • The backward error is at or below u≈10−16u \approx 10^{-16}u≈10−16 for every nnn (a printed 0 means the residual was exactly zero): scipy.linalg.solve is backward stable.

  • The forward error grows with K(A)K(\mathbf{A})K(A). Whenever the backward error is not zero, the forward error stays below K(A)×K(\mathbf{A}) \timesK(A)× backward error, which is a worst case, not a forecast.

  • At n=12n = 12n=12, K(A)∼1016K(\mathbf{A}) \sim 10^{16}K(A)∼1016 and the computed solution has essentially no correct digits, even though the residual is tiny. A small residual says the problem you solved is close to the one you posed, not that the answer is close to the truth.
